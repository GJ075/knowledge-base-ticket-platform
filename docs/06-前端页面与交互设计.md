# 06 前端页面与交互设计

## 1. 设计目标与原则

1. **角色驱动**：菜单和操作按钮按角色显示；后端仍做强制权限校验，前端隐藏只是体验优化。
2. **状态可见**：工单状态、文档索引状态、审核动作都用颜色徽标，用户一眼能看出当前进展。
3. **少跳转**：常用动作在列表或详情页直接完成，避免多层弹窗。
4. **流式体验**：问答逐字显示，支持中止；引用卡片紧贴回答。
5. **工程化**：Next.js App Router + TypeScript + Tailwind + shadcn/ui + TanStack Query；请求、鉴权、错误处理集中封装。

## 2. 技术约定

| 项 | 约定 |
|---|---|
| 框架 | Next.js 15 App Router |
| 语言 | TypeScript |
| 样式 | Tailwind CSS + shadcn/ui |
| 服务端状态 | TanStack Query |
| 表单 | react-hook-form + zod |
| 认证 | JWT 存在 httpOnly Cookie；请求携带 `credentials: "include"` |
| 流式 | `fetch` + `ReadableStream` + `AbortController` |
| 日期 | date-fns，按浏览器本地时区展示 |
| 路由守卫 | 根布局调用 `/auth/me`，未登录跳转 `/login` |

## 3. 路由与页面清单

| 路由 | 页面 | 可见角色 | 用途 |
|---|---|---|---|
| `/login` | 登录 | 公开 | 用户名密码登录 |
| `/chat` | 知识库问答 | 员工、领导 | 多轮问答、引用、流式输出 |
| `/history` | 我的查询历史 | 员工、领导 | 本人会话列表 |
| `/documents` | 文档列表 | 员工、领导 | 搜索、上传、下载、编辑、删除 |
| `/documents/[id]` | 文档详情 | 员工、领导 | 元数据、下载、编辑删除入口 |
| `/documents/approvals` | 文档审批 | 领导 | 审批员工的文档变更 |
| `/tickets` | 工单列表 | 员工、领导 | 筛选、查看、进入详情 |
| `/tickets/new` | 新建工单 | 员工、领导 | 填写并提交工单 |
| `/tickets/[id]` | 工单详情 | 提交人、处理人、领导 | 时间线、附件、状态操作 |

## 4. 全局布局

- **侧边栏**：产品名、导航、当前用户信息。
- **导航项**：问答、我的历史、文档、文档审批（仅领导）、工单、新建工单。
- **顶栏**：当前页面标题、用户显示名、角色徽标、退出登录。
- **响应式**：窄屏时侧边栏折叠为抽屉。
- **登录页**不显示侧边栏。

## 5. 页面详细设计

### 5.1 登录 `/login`

- 居中卡片：用户名、密码、登录按钮。
- 回车提交；提交中禁用按钮。
- 登录失败显示"用户名或密码错误"。
- 登录成功跳转 `/chat`；若带 `next` 参数则跳转该地址。
- 已登录用户访问时直接跳转 `/chat`。

### 5.2 问答 `/chat`

**布局**：左侧会话栏（约 280px）+ 右侧消息区。

**左侧会话栏**：

- "新对话"按钮。
- 本人会话列表，按最后活跃时间倒序。
- 当前会话高亮。
- 每项显示标题和最后更新时间；可删除（二次确认）。
- 不展示其他用户的会话。

**消息区**：

- 用户消息右对齐，助手消息左对齐。
- 助手消息下方显示引用卡片：文档标题 + 片段；首版不做点击跳转。
- 流式输出时显示光标或"生成中"状态。
- 生成中显示"停止"按钮；点击后保留已生成内容。
- 输入框：多行文本，Enter 发送，Shift+Enter 换行；空消息禁止发送。
- 空状态：提示"输入问题，系统会基于企业知识库回答"。
- 拒答时按普通助手消息展示，带信息图标。
- 错误时在消息区显示错误提示和"重试"按钮。

**交互流程**：

1. 首次发送时没有 `conversation_id`，后端创建新会话并通过 `meta` 事件返回。
2. 前端把 `conversation_id` 写入 URL 查询参数，刷新会话列表。
3. 后续发送携带该 `conversation_id`。
4. 打开历史会话时，从 URL 查询参数加载会话详情。

### 5.3 我的历史 `/history`

- 会话列表：标题、最后更新时间、消息数量（可选）。
- 点击进入 `/chat?conversation_id=...`。
- 支持删除会话，二次确认。
- 空状态："还没有问答记录"。

### 5.4 文档列表 `/documents`

**工具栏**：

- 关键词搜索（标题或文件名），输入防抖。
- "上传文档"按钮。

**表格列**：

| 列 | 说明 |
|---|---|
| 标题 | 文档标题 |
| 文件名 | 原始文件名 |
| 大小 | 格式化为 KB/MB |
| 索引状态 | 徽标：待索引 / 索引中 / 可检索 / 索引失败 |
| 上传人 | 显示名 |
| 更新时间 | 本地时间 |
| 操作 | 下载、编辑、删除；领导额外有"重新索引"（失败时） |

**上传对话框**：

- 标题、文件。
- 前端校验扩展名和 50MB 上限。
- 员工提交后提示"已提交审批，等待领导处理"；领导提交后提示"上传成功，正在解析"。
- 提交后刷新列表；索引进度通过轮询或手动刷新查看。

**编辑对话框**：

- 标题、可选新文件。
- 员工提交后生成变更申请；领导直接生效。

**删除**：

- 二次确认。
- 员工删除生成变更申请；领导直接删除。

### 5.5 文档详情 `/documents/[id]`

- 元数据卡片：标题、文件名、大小、上传人、创建/更新时间、索引状态。
- "下载"按钮。
- 员工：编辑、删除（走审批）。
- 领导：编辑、删除、重新索引。
- 首版不做在线预览。

### 5.6 文档审批 `/documents/approvals`（领导）

**标签页**：待审批（默认）、已通过、已驳回。

**表格列**：动作（新增/修改/删除）、目标文档、申请人、提交时间、状态、操作。

**审批详情**：

- 展示变更类型、标题、新文件名、目标文档。
- 审批意见输入框。
- "通过"按钮；"驳回"按钮（必须填写原因）。
- 操作成功后刷新列表并提示。

**空状态**："暂无待审批变更"。

### 5.7 工单列表 `/tickets`

**标题与按钮**："新建工单"。

**筛选**：

- 关键词（标题/描述/工单编号）。
- 状态、类型、优先级。
- 处理人（领导可见）。
- 时间范围。

**表格列**：工单编号、标题、类型、优先级、状态、提交人、处理人、更新时间。

**范围**：

- 员工：自己提交的 + 指派给自己的。
- 领导：全部。

点击行进入工单详情。

### 5.8 新建工单 `/tickets/new`

**表单字段**：

| 字段 | 控件 | 必填 |
|---|---|---|
| 标题 | 输入框 | 是 |
| 描述 | 多行文本 | 是 |
| 补录历史工单 | 复选框 | 否 |
| 原创建时间 | 日期时间选择；仅补录时显示，不能晚于当前 | 否 |
| 提交人 | 员工下拉；仅领导补录时显示，默认自己 | 否 |
| 类型 | 下拉：IT故障/权限申请/资料申请/其他 | 是 |
| 优先级 | 下拉：低/中/高/紧急 | 是 |
| 期望完成时间 | 日期时间选择；普通工单必须晚于当前，补录允许过去 | 否 |
| 附件 | 多文件上传 | 否 |

**提示**：

- 员工："提交后由领导审核，审核通过后进入处理。"
- 领导："提交后进入待分配，请指派处理人。"
- 补录："补录工单创建后进入新建状态，由领导审核；审核通过后直接变为已解决。"

提交成功后跳转工单详情。

### 5.9 工单详情 `/tickets/[id]`

**头部**：工单编号、标题、状态徽标、优先级徽标、类型；补录工单额外显示「补录」徽标。

**元数据**：提交人、处理人、期望完成时间、创建时间（补录时为原创建时间）、更新时间。

**正文**：描述。

**附件**：文件名、大小、上传人、下载按钮。

**时间线**：按时间正序展示事件：操作人、动作、状态变化、备注、时间；补录工单第一项为「补录工单」。

**操作区**：按后端返回的 `available_actions` 渲染：

| 动作 | 控件与规则 |
|---|---|
| `approve` | 审批意见；普通工单状态为 `new` 或 `modified` 且当前无处理人时，可选择处理人（默认提交人）；补录工单不显示处理人，审核通过直接已解决 |
| `reject` | 审批意见必填 |
| `assign` | 员工下拉，必选 |
| `complete` | 处理说明（可选） |
| `modify_complete` | 修改说明（可选） |
| `edit` | 弹出编辑表单；仅 `returned` |
| `confirm_resolved` | 确认已解决，可填备注 |
| `confirm_unresolved` | 备注必填 |
| `add_attachment` | 上传附件；仅 `returned` |
| `delete_attachment` | 删除附件；仅 `returned` |

**版本冲突**：操作请求携带当前 `version`；收到 `409 CONFLICT_VERSION` 时提示"工单已被更新，请刷新后重试"，并自动刷新详情。

**成功反馈**：操作成功后刷新详情和列表，显示 toast。

## 7. 状态与交互规则

1. **加载**：列表和详情使用骨架屏；按钮提交时显示 loading。
2. **空状态**：给出明确文案和下一步动作。
3. **错误**：接口错误显示可读信息；500/网络错误提供重试。
4. **401**：跳转登录页，并记录 `next` 地址。
5. **403**：显示"无权访问该资源"。
6. **409**：版本冲突时刷新详情并提示；业务状态冲突时展示后端消息。
7. **二次确认**：删除、驳回、确认未解决等操作必须弹窗确认。
8. **防重复提交**：请求期间禁用按钮。
9. **不做乐观更新**：变更成功后重新拉取详情和列表，保证状态一致。
10. **权限以服务端为准**：即使按钮被误显示，后端仍会拒绝。

## 8. API 调用与 SSE

### 8.1 API 封装

- `lib/api.ts` 统一处理 base URL、`credentials: "include"`、JSON 解析、错误结构。
- 401 时触发全局登出并跳转登录。
- 所有请求失败时抛出带 `code`、`message`、`status` 的错误对象。

### 8.2 TanStack Query 键

| 数据 | Query Key |
|---|---|
| 当前用户 | `["me"]` |
| 会话列表 | `["conversations"]` |
| 会话详情 | `["conversation", id]` |
| 文档列表 | `["documents", filters]` |
| 文档详情 | `["document", id]` |
| 文档变更 | `["document-changes", filters]` |
| 工单列表 | `["tickets", filters]` |
| 工单详情 | `["ticket", id]` |
| 员工列表 | `["users", "employees"]` |

变更成功后失效相关 key，重新拉取。

### 8.3 SSE 解析

1. 使用 `fetch(POST /chat/stream)`，读取 `response.body`。
2. 用 `TextDecoder` 解码，按 `\n\n` 切分事件块。
3. 解析每块的 `event:` 和 `data:` 行。
4. `meta`：保存 `conversation_id` 和 `user_message_id`。
5. `citations`：保存引用列表。
6. `token`：追加 `delta` 到助手消息。
7. `done`：标记完成，刷新会话列表。
8. `error`：展示错误，保留已生成内容。
9. `AbortController` 在点击"停止"或组件卸载时取消请求。

## 11. 首版不做

- 移动端 App、PWA。
- 深色模式。
- 富文本编辑器；描述使用纯文本。
- 文档在线预览。
- 站内通知、邮件通知。
- 工单评论流（仅事件时间线）。
- 国际化。
- 拖拽上传排序、批量操作。
- 检索准确率相关的 UI（置信度、相似度分数）。
