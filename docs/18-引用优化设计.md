# 18 引用优化设计

> 日期：2026-11-11
> 状态：已实现（2026-11-11），迁移 `0009_citation_usage`
> 关联：[12-评测系统设计](12-评测系统设计.md)、[16-检索优化设计](16-检索优化设计.md)

## 1. 背景

当前问答的引用区固定展示检索 top-5，与问题无关的片段也会出现。原因有三：

1. 引用等于检索结果，不要求模型标注实际使用；
2. 生产默认未开精排、阈值为 0，检索结果不做相关度截断；
3. 文档标题不在分块正文里，同模板文档互相干扰。

本设计把引用从「检索了什么」改为「回答实际用了什么」，并建立可标定的阈值与落差策略。

## 2. 目标

1. 回答中的事实性结论带 `[n]` 标注，点击可定位到片段；
2. 引用卡片只展示被实际引用的片段；
3. 全部片段低于阈值时直接拒答，不调用大模型；
4. 生产默认开启精排，阈值与落差用现有评测集标定；
5. 评测新增「回答引用」口径，与旧「检索引用」指标并存，保证历史可比。

## 3. 已确认决策

| 项 | 决策 |
|---|---|
| 引用含义 | 只展示模型实际引用的片段 |
| 判定方式 | 提示词要求 `[n]` 编号 + 后端校验 |
| 保留策略 | 精排阈值 + 相对落差，动态保留 1–5 条 |
| 精排 | 生产默认开启，每次请求都执行 |
| 阈值来源 | 用现有 81 轮回归集标定 |
| 编号缺失 | 回退：保留全部达标片段，标记 `fallback=true` |
| 零片段 | 直接拒答，不调用大模型 |
| SSE 时序 | 生成前发候选，生成结束再发实际引用 |
| 前端 | 内联可点击编号 + 侧栏卡片联动 |
| 历史消息 | 打开会话时重算（见 7.3 的限制说明） |

## 4. 检索与生成流程

```text
候选召回（dense + sparse）
    ↓
精排（始终执行，失败则跳过阈值，见 4.2）
    ↓
阈值 + 相对落差过滤
    ↓ 0 条 → 直接拒答（不调用模型）
构造上下文（带 [n] 编号与文档标题）
    ↓
模型生成，要求每条结论标注 [n]
    ↓
解析编号、校验范围、去重
    ↓ 无有效编号 → fallback 全部达标片段
保存 used_citations
```

### 4.1 保留规则

设精排后第一条分数为 `top1`：

```text
keep(item) = item.score >= rerank_threshold
         and item.score >= top1 - rerank_delta
```

- 初始值：`rerank_threshold=0.30`、`rerank_delta=0.15`，最终值由标定确定；
- 最多保留 `final_k`（默认 5）条；
- 过滤后为空 → 拒答话术「根据现有知识库，我无法回答这个问题。」，引用为空。

### 4.2 精排失败的处理

精排调用失败时回退融合排序。此时分数是 RRF 尺度，**不得应用阈值与落差**，否则会把结果全部过滤。实现上记录 `rerank_ok` 标志，阈值过滤只在 `rerank_ok=true` 时执行，并在响应里标记 `degraded=true`。

### 4.3 提示词

系统提示新增两条约束：

```text
1. 只能依据提供的资料回答；每条结论后用 [编号] 标注来源。
2. 资料不足以回答时，直接说明无法回答，不要编造，也不要给出未标注的来源。
```

上下文编号与候选顺序一致，标题与章节一并传入：

```text
[1] 文档《费用报销管理规范》 章节：总则
正文……
```

## 5. SSE 协议

新增事件，保持向后兼容（旧客户端忽略未知事件即可）：

```text
event: citations
data: {"items": [候选片段...], "threshold": 0.30, "delta": 0.15}

event: token
data: {"delta": "..."}

event: used_citations
data: {"items": [{"index": 4, ...片段信息}], "fallback": false, "invalid_refs": 0}

event: done
data: {"assistant_message_id": "UUID"}
```

- `citations`：过滤后的候选，带 `score`、`heading_path`；
- `used_citations`：从回答中解析出的实际引用，按首次出现顺序；
- `fallback=true`：模型未输出有效编号，引用等于候选；
- `invalid_refs`：越界编号数量，用于观测模型遵循度。

## 6. 解析与校验

```text
refs = 正则 \[(\d+)\] 去重
refs = refs 中 1 <= n <= len(candidates) 的部分
invalid = 被丢弃的数量
```

规则：

- 同一编号重复出现只计一次；
- 越界编号忽略，计入 `invalid_refs`；
- `refs` 为空 → `fallback=true`，引用取全部候选；
- 回答中出现拒答话术时，引用置空，不触发 fallback。

## 7. 数据与前端

### 7.1 存储

`messages` 增加：

| 列 | 类型 | 说明 |
|---|---|---|
| `citation_meta` | `jsonb NULL` | `{mode, fallback, invalid_refs, candidate_count}` |

`citations` 字段语义改为「实际引用」；旧消息没有 `citation_meta`，按旧格式展示。

### 7.2 前端

- 回答文本中的 `[n]` 渲染为可点击标记，点击高亮右侧对应卡片；
- 引用卡片只列出 used citations，显示文档名、章节、分数、片段；
- `fallback=true` 时卡片标题显示「未标注编号，展示达标片段」；
- 候选数量与实际引用数量可放在折叠区，便于排查。

### 7.3 历史消息重算（有限制）

用户选择「打开时重算」，需要说明限制：

- 旧回答里没有 `[n]` 编号，**无法还原“当时实际用了哪几条”**；
- 可行的做法是：打开会话时按新检索管线重新跑一遍，把阈值过滤后的片段作为**候选引用**展示，并标注「按当前策略重算」；
- 不覆盖原始 `citations` 数据，避免篡改历史；
- 重算有成本：每条消息一次检索 + 精排。实现上做懒加载与缓存，同一消息只算一次。

如果希望历史记录也精确，只能重新生成回答，代价与风险更高，暂不纳入首版。

## 8. 评测口径

新增指标，保留旧指标：

| 指标 | 定义 |
|---|---|
| 检索引用命中（旧） | 必引文档是否出现在候选 |
| 检索引用精确率（旧） | 候选中的必引文档占比 |
| 回答引用命中（新） | 必引文档是否出现在 used citations |
| 回答引用精确率（新） | used citations 中的必引文档占比 |
| 引用非法率 | `invalid_refs / 总编号数` |
| fallback 率 | 未输出编号的轮次占比 |
| 零片段拒答率 | 阈值过滤后为空而拒答的比例 |

`eval_run_items` 增加对应列（迁移 0009），历史运行保持旧口径。

## 9. 阈值标定

在现有 81 轮回归集上网格扫描：

- 阈值：0.10–0.60，步长 0.05；
- 落差：0.05 / 0.10 / 0.15 / 0.20；
- 每组跑一次评测，记录命中率、回答通过率、回答引用精确率、拒答率、平均耗时。

选择规则：

1. 回答通过率相对基线下降不超过 2 个百分点；
2. 回答引用精确率优先；
3. 平均耗时不超过基线 2 倍。

注意：81 轮样本偏小，标定结果可能过拟合；上线后保留同一批用例每月复测，阈值变更需记录原因。

## 10. 配置

| 配置 | 默认 | 说明 |
|---|---|---|
| `RERANK_ENABLED` | `true` | 生产默认开启 |
| `RERANK_THRESHOLD` | 标定值（初始 0.30） | 精排分数下限 |
| `RERANK_DELTA` | 标定值（初始 0.15） | 与 top1 的最大落差 |
| `CITATION_REQUIRED` | `true` | 要求模型输出编号 |
| `FINAL_K` | `5` | 候选上限 |

跨字段校验：`threshold > 0` 或 `delta > 0` 时必须 `rerank_enabled=true`。

## 11. 验收标准

1. 回答包含 `[n]` 编号，点击可高亮对应卡片；
2. 引用卡片数量等于实际引用数量，不再是固定 5 条；
3. 阈值过滤后为空时，直接拒答且不产生模型调用；
4. 模型未输出编号时，回退展示达标片段并标记 fallback；
5. 越界编号被忽略并计入 `invalid_refs`；
6. 精排失败时跳过阈值，标记 degraded，不出现「全部过滤」；
7. 评测新增回答引用指标，历史数据仍可查看旧口径；
8. 旧会话打开时展示「按当前策略重算」的候选引用，不覆盖原数据。

| B | 提示词编号、解析器、used citations 存储与 SSE 事件 |

## 13. 风险

- 生产默认开精排，CPU 上单次问答增加 3–5 秒；
- 模型可能不按格式输出编号，fallback 率需要观测；
- 81 轮标定样本偏小，阈值可能过拟合；
- 历史消息重算只能给「候选」，无法还原真实引用，需要在 UI 明确标注；
- 阈值过高会先过滤掉正确片段，需以评测集为准，不靠直觉调参。

| 单元测试 | `server/tests/test_citations.py` |

实现过程中的关键调整：

1. **精排输入加入文档标题**。实测发现同一模板文档在精排中分数接近，正确文档被噪声压在后面；在 `_rerank` 中传入「《标题》\n正文」后，费用报销问题的候选分数从 0.65/0.96 变为 0.996/0.99/0.94，噪声文档被排除。这一步不在原设计内，但没有它，阈值与落差会把正确答案一起过滤。
2. 精排失败时返回 `rerank_ok=false`，跳过阈值过滤并标记 `degraded`，避免 P0-3 的「全部过滤」问题。
3. 初始配置：`RERANK_ENABLED=true`、`RERANK_THRESHOLD=0.3`、`RERANK_DELTA=0.15`；阈值标定尚未执行，当前值以线上实测为准。
4. 评测新增 `used_citation_hit/precision`、`invalid_refs`、`citation_fallback`、`rerank_degraded` 字段与汇总指标，旧指标保留。

已验证：

- 费用报销问题：候选 3 条全部来自《费用报销管理规范》，回答带 `[1]`，保存的 `citations` 为 1 条；
- 评测单条运行：`answerable_used_citation_hit_rate=1.0`、`answerable_avg_used_citation_precision=1.0`、`invalid_refs_total=0`；
- 前端点击 `[1]` 可高亮对应卡片，控制台无报错。
