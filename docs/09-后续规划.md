# 09 后续规划

> 本文件只做规划，不进入首版代码。特别是**拒答阈值、置信度提示、人工兜底、审计记录**，首版明确不实现。

## 1. 二期功能

| 功能 | 说明 | 优先级建议 |
|---|---|---|
| Agent 工单分类与辅助填写 | 用户描述问题后，Agent 判断工单类型、预填标题/描述、建议优先级 | 高 |
| 工单解决方案沉淀 | 已解决工单生成知识候选，领导审核后进入知识库 | 高 |
| 站内通知 | 工单指派、驳回、待确认时通知相关人 | 中 |
| SLA 与超时升级 | 按优先级设置处理时限，超时提醒或升级 | 中 |
| 文档版本历史 | 保留每次变更的版本，可查看和回滚 | 中 |
| 文档级权限 | 按部门或角色限制文档可见范围 | 中 |
| 多领导/多级审批 | 支持部门领导和上级领导 | 中 |
| 工单评论与协作 | 处理人、提交人、领导在工单内讨论 | 中 |
| 工单关闭与重开 | 已解决后由申请人确认关闭，或申请重开 | 低 |
| 多租户 | 一套系统服务多家公司，数据隔离 | 低 |
| 报表与统计 | 工单量、解决时长、知识库使用量 | 低 |

## 2. 检索与生成优化

### 2.1 检索

- 引入 reranker（如 BGE-reranker-v2-m3），对 top-20 粗排后取 top-5。
- BM25 + 向量混合检索，提升专有名词和编号类问题的召回。
- Query rewrite：结合多轮上下文改写检索问题。
- 多查询扩展：对一个问题生成多个检索表达。
- 语义切分：按标题、段落、表格结构切分，替代固定长度切分。
- 元数据过滤：按文档类型、部门、时间过滤。

### 2.2 生成与可信度

- 引用编号解析：要求模型输出 `[1]`，后端只保留真实引用的片段。
- 答案忠实度检查：校验回答是否被引用片段支持。
- 拒答阈值：基于检索相似度或重排分数，低于阈值直接拒答。
- 置信度提示：在回答旁展示"高/中/低置信度"。
- 人工兜底：低置信度时建议转工单或人工客服。
- 答案评测：建立问题集，定期评估准确率和引用正确率。

## 3. 审计与合规

首版只保留工单事件时间线，不做独立审计系统。后续建议：

- 登录日志：登录成功/失败、IP、时间、客户端。
- 操作审计：文档上传/审批/删除、工单所有状态变化、权限变更。
- 数据访问审计：谁在什么时候检索了哪些文档片段。
- 数据保留策略：日志留存周期、工单留存周期、文档删除后的清理。
- 数据导出与脱敏：按合规要求导出，敏感字段脱敏。
- 权限复核：定期检查账号和角色。

## 4. 生产化

| 方向 | 内容 |
|---|---|
| 部署 | 服务器部署、Nginx/Caddy 反向代理、HTTPS |
| 存储 | PostgreSQL/Redis/对象存储替换为云托管或高可用集群 |

| 安全加固 | CSRF token、限流、文件病毒扫描、依赖漏洞扫描 |
| 压测 | 并发问答、批量入库、工单并发操作 |

## 5. 评测体系

| 指标 | 说明 |
|---|---|
| Recall@k | 正确片段是否出现在检索结果中 |
| MRR | 正确片段在检索结果中的排名 |
| Answer Accuracy | 回答是否正确 |
| Faithfulness | 回答是否忠实于引用片段 |
| Citation Precision | 引用片段是否真正支持回答 |
| Citation Recall | 回答涉及的事实是否都有引用 |
| Refusal Correctness | 该拒答时是否拒答，不该拒答时是否误拒 |
| Ticket Resolution Time | 工单平均解决时长 |
| Reopen Rate | 工单重开率（后续支持重开后） |

## 6. 首版明确不做的项

| 项 | 首版 | 后续 |
|---|---|---|
| 拒答阈值 | 不做，仅 prompt 约束 | 引入相似度/重排阈值 |
| 置信度提示 | 不做 | 回答旁展示置信度 |
| 人工兜底 | 不做 | 低置信度转工单/人工 |
| 审计记录 | 只做工单事件时间线 | 独立审计系统 |
| reranker | 不做 | BGE-reranker |
| 混合检索 | 不做 | BM25 + 向量 |
| OCR | 不做 | 扫描件解析 |
| Agent 工单辅助 | 不做 | 分类、预填、建议 |
| 工单入知识库 | 不做 | 知识候选 + 审批 |
| 通知 | 不做 | 站内/邮件 |
| 文档版本历史 | 不做 | 版本与回滚 |
| 文档级权限 | 不做 | 部门/角色 ACL |
| 多租户 | 不做 | 租户隔离 |
| 服务器部署 | 仅预留 | 正式生产部署 |

## 7. 迭代顺序建议

1. **先修 P0/P1**：启动、主流程、权限漏洞。
2. **再补 P2**：提示、筛选、附件、异常处理。
3. **检索优化**：reranker、混合检索、query rewrite、评测集。
4. **可信度与兜底**：引用校验、拒答阈值、置信度、人工兜底。
5. **审计与权限**：登录日志、操作审计、文档级权限。
6. **Agent 与知识沉淀**：工单分类、辅助填写、工单转知识。
7. **生产化**：部署、监控、备份、安全加固。

每一轮迭代都要同步更新需求、API、状态机和测试手册，避免文档与代码脱节。
