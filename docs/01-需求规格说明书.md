## 2. 项目背景与目标

企业内部的制度、流程、技术资料分散在 PDF、Word、Markdown 等文件中，员工查找成本高；同时，员工遇到问题时缺少统一的问题上报、审批、指派、跟踪机制。

本项目建设一套单租户的企业知识库问答与工单处理系统，目标：

1. 员工和领导通过自然语言快速获取企业文档中的答案，并给出可核验的引用。
2. 员工对知识库的变更经过领导审批，保证知识内容可控。
3. 工单从提交、审核、指派、处理、修改到解决有明确的状态和责任人。
4. 首版完成可运行的主体框架，后续通过测试和迭代完善。

## 3. 术语

| 术语 | 说明 |
|---|---|
| 知识库 | 企业文档及其切分后的向量集合 |
| 文档 | 上传到系统的 PDF / DOCX / Markdown / TXT 文件 |
| 变更申请 | 员工对文档新增、修改、删除的待审批记录 |
| 工单 | 员工或领导提交的问题或申请，按状态机流转 |
| 处理人 | 当前负责处理工单的员工 |
| 审核人 | 领导，负责初次审核、修改审核、最终审核 |
| 待用户确认 | 领导提交的工单在处理完成后，由提交领导确认是否解决 |
| 引用 | 回答所依据的文档名和片段 |

## 4. 用户角色与权限概览

| 能力 | 员工 | 领导 |
|---|---|---|
| 登录、问答 | 可以 | 可以 |
| 查看问答历史 | 仅自己 | 仅自己，不能查看员工的 |
| 查看文档、下载文档 | 可以 | 可以 |
| 新增 / 修改 / 删除文档 | 提交变更申请，需审批 | 直接生效 |
| 文档审批 | 不可以 | 可以 |
| 提交工单 | 可以 | 可以 |
| 补录历史工单 | 只能补录自己的 | 可指定任意员工作为提交人 |
| 指定处理人 | 不可以 | 可以 |
| 审核工单（初次、修改、最终） | 不可以 | 可以 |
| 确认领导工单是否解决 | 不可以 | 提交该工单的领导可以 |
| 查看工单 | 自己提交的 + 指派给自己的 | 全部 |

## 5. 功能需求

### 5.1 认证与账号

| 编号 | 需求 |
|---|---|
| FR-AUTH-01 | 用户使用用户名和密码登录，成功后获得访问令牌。 |
| FR-AUTH-02 | 系统预置 1 个领导、2 个员工账号，不提供注册。 |
| FR-AUTH-03 | 未登录访问受保护接口返回 401；已登录但越权返回 403。 |
| FR-AUTH-04 | 前端根据当前角色显示菜单和操作按钮；后端仍强制校验权限。 |

### 5.2 知识库问答

| 编号 | 需求 |
|---|---|
| FR-CHAT-01 | 支持多轮对话，保留最近 5 轮上下文。 |
| FR-CHAT-02 | 每次回答检索 top-5 文档片段，答案必须附带引用（文档名 + 片段）。 |
| FR-CHAT-03 | 知识库中没有相关内容时，回答固定拒答话术；首版不设相似度阈值，由提示词约束模型判断。 |
| FR-CHAT-04 | 回答使用 SSE 流式输出。 |
| FR-CHAT-05 | 会话历史仅本人可见，领导也不能查看员工的问答历史。 |
| FR-CHAT-06 | 用户可以查看会话列表、打开历史会话继续提问。 |

### 5.3 文档管理与审批

| 编号 | 需求 |
|---|---|
| FR-DOC-01 | 支持 PDF、DOCX、Markdown、TXT；单文件不超过 50MB；首版不做 OCR。 |
| FR-DOC-02 | 员工新增、修改、删除文档时生成待审批的变更申请。 |
| FR-DOC-03 | 审批期间：新增文档不可检索；修改、删除的旧版本继续可检索。 |
| FR-DOC-04 | 领导新增、修改、删除文档直接生效。 |
| FR-DOC-05 | 领导在独立的"文档审批"页面通过或驳回变更；驳回必须填写原因。 |
| FR-DOC-06 | 变更通过后异步解析、固定长度切分、BGE-M3 embedding，并写入 pgvector。 |
| FR-DOC-07 | 文档列表支持关键词搜索和下载；首版不提供在线预览。 |
| FR-DOC-08 | 首版不做版本历史；修改通过后以新内容替换旧分块。 |
| FR-DOC-09 | 所有生效文档对所有已登录用户可见、可检索，不做文档级权限。 |
| FR-DOC-10 | 文档列表展示索引状态；领导可以对索引失败的文档重新索引。 |

### 5.4 工单管理

| 编号 | 需求 |
|---|---|
| FR-TICKET-01 | 创建工单，字段：标题、描述、类型、附件、优先级、期望完成时间。 |
| FR-TICKET-02 | 类型固定为 `IT故障 / 权限申请 / 资料申请 / 其他`；优先级为 `低 / 中 / 高 / 紧急`。 |
| FR-TICKET-03 | 员工提交后状态为 `new`；领导审核通过后进入 `in_progress`，审核时指定处理人，默认提交人；审核不通过进入 `returned`。 |
| FR-TICKET-04 | 领导提交后状态为 `pending_assignment`；领导指派处理人后进入 `in_progress`。 |
| FR-TICKET-05 | 处理人标记完成：员工工单进入 `completed`；领导工单进入 `pending_user_confirmation`。 |
| FR-TICKET-06 | 员工工单 `completed` 后，领导审核通过进入 `resolved`，不通过进入 `returned`。 |
| FR-TICKET-07 | 领导工单 `pending_user_confirmation` 后，提交领导确认已解决进入 `resolved`，未解决进入 `returned`。 |
| FR-TICKET-08 | `returned` 后处理人修改工单并标记 `modified`；领导审核通过回到 `in_progress`，不通过回到 `returned`。 |
| FR-TICKET-09 | 工单列表支持关键词、状态、类型、优先级、处理人、时间筛选；可直接打开详情并下载附件。 |
| FR-TICKET-10 | 员工只能查看自己提交的和指派给自己的工单；领导可以查看全部工单。 |
| FR-TICKET-11 | 每次状态变化写入工单事件，详情页展示时间线。 |
| FR-TICKET-12 | 非法状态转换返回 409；越权操作返回 403。 |
| FR-TICKET-13 | 工单完成后只作为工单记录保存和查询，不进入 RAG 知识库。 |
| FR-TICKET-14 | 支持补录历史工单：员工可补录自己的，领导可指定员工作为提交人；可填原创建时间和过去的期望完成时间；补录创建后进入 `new`，领导审核通过直接 `resolved`，不通过进入 `returned`。普通新建工单的期望完成时间必须晚于当前时间。 |

### 5.5 查询与历史

| 编号 | 需求 |
|---|---|
| FR-HIST-01 | 提供"我的查询历史"页面，列出本人会话记录。 |
| FR-HIST-02 | 工单记录可查询、可打开详情、可下载附件。 |

## 6. 非功能需求

### 6.1 性能与规模

| 编号 | 需求 |
|---|---|
| NFR-PERF-01 | 设计目标：500 用户、1 万文档、100 工单/天；首版本机演示。 |
| NFR-PERF-02 | 非 LLM 接口 p95 小于 500ms（本机、1 万文档以内）。 |
| NFR-PERF-03 | 首 token 延迟目标小于 8 秒（本机、DeepSeek 网络正常）。 |

### 6.2 安全与数据边界

| 编号 | 需求 |
|---|---|
| NFR-SEC-01 | 密码哈希存储；JWT 认证；基于角色的访问控制。 |
| NFR-SEC-02 | 文档原文、向量、附件只存本机；仅"用户问题 + top-5 检索片段"发送到 DeepSeek。 |
| NFR-SEC-03 | 校验文件类型和大小；防止路径穿越；使用 ORM 防止 SQL 注入。 |
| NFR-SEC-04 | 日志不记录密码、令牌和完整文档内容。 |

### 6.3 可用性与工程化

| 编号 | 需求 |
|---|---|
| NFR-OPS-01 | Docker Compose 一键启动后端依赖。 |
| NFR-OPS-02 | 使用 `.env` 管理配置，不提交密钥。 |
| NFR-OPS-03 | 使用 Alembic 管理迁移；提供健康检查、结构化日志和 OpenAPI 文档。 |
| NFR-OPS-04 | 依赖服务失败时返回明确错误码和可读信息。 |

### 6.4 兼容性

| 编号 | 需求 |
|---|---|
| NFR-COMP-01 | Windows 11 + Docker Desktop；Chrome / Edge 最新版。 |
| NFR-COMP-02 | 首版本机部署，预留服务器部署配置。 |

## 7. 首版范围

### 7.1 首版包含

- 登录、JWT、员工/领导两种角色、预置账号。
- 文档上传、解析、切分、embedding、向量检索。
- 文档列表、搜索、下载。
- 员工文档变更审批（新增、修改、删除）。
- RAG 多轮问答、SSE 流式输出、引用、拒答。
- 会话历史（仅本人可见）。
- 工单创建、列表、详情、筛选、附件。
- 员工工单与领导工单的完整状态机。
- 工单事件时间线。
- Docker Compose、Alembic、健康检查、结构化日志、OpenAPI。
- 首版测试手册。

### 7.2 首版不包含

- reranker、BM25 混合检索、query rewrite。
- OCR、扫描件解析。
- Agent 工单分类与辅助填写。
- 工单解决方案写入知识库。
- 通知、SLA 计时、自动升级。
- 审计 UI、登录日志、操作日志。
- 拒答阈值、置信度提示、人工兜底。
- 文档级权限、版本历史、多租户。
- 服务器生产部署、HTTPS、监控、备份。

## 8. 验收标准（高层）

1. 领导上传一份 PDF，文档出现在列表并可被问答检索。
2. 员工上传一份文档，状态为待审批；领导通过后可检索；驳回后不可检索。
3. 员工修改或删除文档，审批期间旧版本仍可检索；通过后新版本生效或文档被删除。
4. 提问命中知识库时，返回流式答案和引用；未命中时返回固定拒答话术。
5. 员工工单可走完：新建 → 领导通过 → 处理中 → 处理完成 → 领导审核 → 已解决；以及所有回退路径。
6. 领导工单可走完：新建 → 待分配 → 指派 → 处理中 → 待用户确认 → 已解决；以及未解决回退路径。
7. 员工只能看到自己的问答历史和权限范围内的工单；领导能看到全部工单但不能看员工问答历史。
8. 非法状态转换和越权操作被拒绝，并返回明确错误。

## 9. 假设与约束

1. 单租户，仅员工和领导两种角色。
2. 领导角色唯一，不区分部门；首版不做多领导审批。
3. 员工提交的工单最终由领导终审；领导提交的工单由提交领导确认。
4. 工单完成后只保存记录，不进入知识库。
5. 首版使用固定长度切分和 top-5 向量检索，不追求准确率。
6. BGE-M3 在本机 GPU 运行；生成调用 DeepSeek API。
7. 首版由用户按测试手册测试，发现问题后再迭代。
