# 08 首版测试手册

> 状态：首版交付版（2026-11-10）。以下命令、端口、账号、地址均按当前项目实际配置整理。

## 1. 测试目标与范围

验证首版主体框架是否走通：

- 登录与角色权限。
- 文档上传、审批、解析、索引、检索。
- RAG 问答、引用、拒答、多轮、历史隔离。
- 员工工单与领导工单的全部状态路径。
- 附件、筛选、时间线、错误处理。

不验证：检索准确率、回答质量、UI 精细度、性能压测、生产部署。

## 2. 环境准备

### 2.1 前置条件

1. Windows 11（或 Linux/macOS），Docker Desktop 已启动。
2. Node.js 20+ 与 npm 已安装（仅前端需要）。
3. 浏览器：Chrome 或 Edge 最新版。
4. 如需真实问答，准备可用的 `DEEPSEEK_API_KEY`。

Docker 拉镜像失败时，需要在 Docker Desktop → Settings → Resources → Proxies 配置代理（本机环境为 FlClash `127.0.0.1:7890`）。

### 2.2 启动后端

```bash
cd infra
cp .env.example .env
```

PowerShell 用：

```powershell
Copy-Item .env.example .env
```

编辑 `infra/.env`，确认 `JWT_SECRET` 和 `DEEPSEEK_API_KEY`，然后：

```bash
docker compose up -d --build
```

GPU 模式：

```bash
docker compose -f docker-compose.yml -f docker-compose.gpu.yml up -d --build
```

等待容器 healthy，检查：

```bash
curl.exe http://localhost:8000/health/ready
```

预期 database、redis、minio、embedding 均为 `ok`。

### 2.3 启动前端

另开一个终端，在项目根目录执行：

```bash
cd web
npm install
npm run dev
```

### 2.4 地址与端口

| 服务 | 地址 |
|---|---|
| 前端 | `http://localhost:3000` |
| API 文档 | `http://localhost:8000/docs` |
| 健康检查 | `http://localhost:8000/health/ready` |
| Embedding | `http://localhost:8001/health` |
| MinIO 控制台 | `http://localhost:9011`（minioadmin / minioadmin） |

宿主机映射端口：PostgreSQL `5433`、Redis `6380`、MinIO `9010/9011`，用于避开本机其他项目的端口占用。

### 2.5 测试接口时的注意事项

1. PowerShell 中测试接口使用 `curl.exe`，不要用 `curl`（它是 `Invoke-WebRequest` 别名）。
2. Windows 终端直接传中文可能乱码；验证中文请用浏览器、UTF-8 文件或 Python `httpx`，不要用 `curl -d "中文"` 判断接口问题。
3. 登录接口使用 Cookie 鉴权，命令行测试需要保存 Cookie：

```bash
curl.exe -c cookies.txt -H "Content-Type: application/json" -d "{\"username\":\"leader\",\"password\":\"Leader@123\"}" http://localhost:8000/api/v1/auth/login
```

### 2.6 重置测试数据

仅测试环境使用。`down -v` 会删除 `pgdata`、`redisdata`、`miniodata` 和 `hf_cache` 四个数据卷，数据库、MinIO 文件和 BGE-M3 模型缓存都会清空，重启后需要重新下载模型：

```bash
cd infra
docker compose down -v
docker compose up -d --build
```

## 7. 常见排查

| 现象 | 排查方向 |
|---|---|
| 页面打不开 | `docker compose ps`；前端 `npm run dev` 是否运行；3000 端口是否被占用 |
| Docker 拉镜像超时 | Docker Desktop 是否配置代理；FlClash 是否运行；必要时重试 |
| 登录后立即退出 | Cookie 是否被浏览器拦截；CORS 是否允许 `http://localhost:3000`；`COOKIE_SECURE` 是否与访问协议一致 |
| 文档一直“索引中” | 查看 `docker compose logs worker`；`embedding` 是否 healthy；MinIO 是否可下载 |
| 文档“索引失败” | 查看 worker 错误；PDF 是否有文本层；先对照已知问题 001 |
| 问答没有引用 | 是否有 `ready` 文档；`document_chunks` 是否有数据；`TOP_K` 是否正常 |
| 问答报错或拒答 | `DEEPSEEK_API_KEY` 是否有效；网络是否可达；embedding 是否可用 |
| 工单按钮不显示 | 查看详情接口的 `available_actions`；确认当前用户、角色和工单状态 |
| 409 版本冲突 | 刷新详情后重新执行；确认没有多标签页同时操作 |
| MinIO 上传失败 | 桶 `kb-documents`、`ticket-attachments` 是否存在；密钥是否正确 |
| VS Code 终端提示 `npm` 无法识别 | 用完整路径 `& "C:\Users\Lenovo\AppData\Local\nodejs\npm.cmd" run dev`；或在终端刷新 PATH；确认重启的是整个 VS Code 而不是只开新标签 |
| 登录页直接是 leader 账号 | 已知问题 003，不是登录失败 |
| 日期筛选结果不对 | 已知问题 006，UTC+8 下偏移 8 小时 |
| 工单标题较长时 500 或断开 | 已知问题 005，标题超过 255 字符 |

## 8. 测试完成标准

1. A、B、C、D、E 的 P0/P1 用例全部通过。
2. 不存在越权访问：员工不能看未授权工单、不能审批、不能看他人问答历史。
3. 员工工单和领导工单各至少走通一条完整正向路径和一条回退路径。
4. 文档新增、修改、删除审批各至少验证一次。
5. 所有失败用例都有记录，能复现，附日志或截图。
6. 已知限制与真实缺陷分开记录，避免把"首版不做"误判为 bug。
