## 1. 背景与目标

当前 RAG 问答存在一个明显现象：回答本身可能正确，但引用区会带出 top-k 检索到的无关片段，例如重复的《员工手册》和测试文档。系统目前没有量化手段判断：

- 检索是否命中正确文档；
- 引用里有多少是噪声；
- 回答是否正确；
- 无答案问题是否拒答；
- 改动切分、检索、提示词后，效果是变好还是变差。

本设计增加一套**离线评测系统**，目标是：

1. 用固定数据集反复运行，得到可比较的指标；
2. 保存每次运行结果，支持手动选择基线做回归对比；
3. 展示失败用例和失败原因，定位检索、引用或回答问题；
4. 支持单轮和多轮 RAG 问答；
5. 不污染真实问答历史。

首版定位是“研发回归工具”，不是在线用户评分，也不是自动调参系统。

## 2. 范围

### 2.1 首版包含

- RAG 问答评测，不覆盖工单流程。
- 单轮和多轮用例，逐轮评分。
- 检索命中、引用准确率、回答正确性、拒答正确性四类指标。
- 多个评测数据集。
- 手工新增用例、JSONL 导入/导出。
- 后台异步运行、进度、取消。
- 历史运行、手动选择基线、指标对比。
- 领导 + 被授权员工使用。
- 初始约 30 条单轮 + 10 条多轮草稿，人工审核后导入。

### 2.2 首版不包含

- 工单状态机/权限的自动化评测。
- reranker、混合检索、生产检索策略改造。
- 自动回归门槛和 CI 阻断。
- 多评委、人工打分工作台、在线 A/B。
- 定时跑分和告警。
- 自动修改提示词或调参。

## 4. 角色与权限

### 4.1 权限模型

- 新增 `users.can_evaluate boolean default false`。
- `leader` 角色天然拥有评测全部权限，不依赖该字段。
- 领导可以在评测页“成员权限”中给员工开启/关闭 `can_evaluate`。
- 被授权员工可以：
  - 查看评测入口和数据集；
  - 新增、修改、删除数据集、用例、轮次；
  - 启动评测、取消自己发起的运行；
  - 查看运行结果和导出报告。
- 被授权员工不能：
  - 给其他人授权；
  - 查看无权限的评测数据（首版评测数据对所有评测人员共享）。
- 未授权员工访问评测接口返回 `403`，导航不显示“评测”。

### 4.2 依赖

后端新增依赖：

```python
def require_evaluator(user=Depends(get_current_user)):
    if user.role != "leader" and not user.can_evaluate:
        raise AppError("AUTH_FORBIDDEN", "没有评测权限", 403)
    return user
```

`/auth/me` 和登录响应增加 `can_evaluate`，前端据此显示导航和页面。

## 6. 用例模型与 JSONL

### 6.1 用例结构

一个用例由 1–5 个轮次组成：

- 单轮：1 个 `turn`；
- 多轮：多个 `turn` 顺序执行，历史对话在内存中累积；
- 每一轮独立评分；
- 用例通过 = 所有有效轮次通过。

### 6.2 JSONL 格式

一份 JSONL 文件代表一个数据集，第一行是数据集元信息，后续每行一个用例：

```jsonl
{"type":"dataset","name":"RAG 回归集 v1","description":"员工手册与流程类问题"}
{"type":"case","title":"食堂开放时间","tags":["single_turn","answerable"],"turns":[{"question":"公司食堂开放时间是什么？","reference_answer":"11:30-13:00","expected_type":"answerable","required_document_titles":["员工手册"]}]}
{"type":"case","title":"班车多轮","tags":["multi_turn","answerable"],"turns":[{"question":"公司班车几点出发？","reference_answer":"18:30","expected_type":"answerable","required_document_titles":["班车说明"]},{"question":"途经哪里？","reference_answer":"地铁站","expected_type":"answerable","required_document_titles":["班车说明"]}]}
{"type":"case","title":"无答案问题","tags":["single_turn","unanswerable"],"turns":[{"question":"公司食堂今天午餐是什么？","reference_answer":null,"expected_type":"unanswerable","required_document_titles":[]}]}
```

导入规则：

- 按 `required_document_titles` 查文档；
- 标题不存在或重复时，该用例导入失败并返回具体行号；
- 导入成功后保存为文档 UUID；
- `answerable` 必须有参考答案和至少一个必引文档；
- `unanswerable` 不要求参考答案和必引文档；
- 单用例最多 5 轮；
- 导入采用“全部校验后写入”，避免半份数据集。

### 6.3 手工编辑

前端支持：

- 新增/编辑/删除用例；
- 增加/删除轮次；
- 从 `ready` 文档中多选必引文档；
- 设置 `answerable` / `unanswerable`；
- 调整轮次顺序；
- 启用/停用用例（用 `tags` 或后续 `is_active` 字段；首版用删除代替停用）。

## 7. 指标定义

设一轮的必引文档集合为 `R`，检索 top-k 文档集合为 `D`，引用文档集合为 `C`。

| 指标 | 定义 | 是否通过门槛 |
|---|---|---|
| 检索命中 `retrieval_hit` | `R ∩ D` 非空 | 是 |
| 检索召回 `recall@k` | `|R ∩ D| / |R|` | 展示 |
| MRR | 第一个命中必引文档的排名倒数；未命中为 0 | 展示 |
| 引用命中 `citation_hit` | `R ∩ C` 非空 | 展示 |
| 引用精确率 | `|R ∩ C| / |C|`；`C` 为空时为 0 | 展示 |
| 回答得分 | DeepSeek 1–5 分 | ≥4 通过 |
| 拒答正确 | 不可回答轮次正确拒答；可回答轮次不应拒答 | 是 |

### 7.1 单轮通过规则

- `answerable`：`judge_score >= 4` 且 `retrieval_hit = true` 且未拒答；
- `unanswerable`：`refused = true`；
- 引用精确率只展示，不作为通过门槛，避免首版因引用噪声全部失败；
- 文档失效、执行错误、评分失败：该轮 `status` 分别为 `invalid` / `error`，不计入通过。

### 7.2 聚合指标

每次运行计算：

- 有效轮次数、通过轮次数、轮次通过率；
- 可回答轮次：平均回答得分、回答通过率、检索命中率、平均 Recall@K、MRR、引用命中率、平均引用精确率；
- 不可回答轮次：拒答正确率；
- 可回答轮次误拒率；
- 用例通过率（所有轮次通过的用例数 / 有效用例数）；
- 失效/错误轮次数。

多轮用例的指标按轮次宏平均，同时保留用例级通过率。

## 8. 检索模式

评测运行参数 `retrieval_mode`：

### 8.1 `question`（当前行为）

- 只用当前轮问题向量化检索；
- 历史对话只用于生成答案；
- 用于建立当前系统基线。

### 8.2 `rewritten`（历史改写）

- 多轮时，先用 DeepSeek 结合历史生成一个独立检索问题；
- 用改写后的问题检索；
- 生成答案仍使用原始问题 + 历史 + 检索上下文；
- 改写结果保存到 `eval_run_items.retrieval_query`；
- 改写失败时回退到原问题，并记录警告；
- 单轮用例改写模式与当前模式等价。

同一数据集建议分别跑 `question` 和 `rewritten` 两次运行，再手动选基线对比。

### 8.3 改写提示词

输入最近 3 轮对话和当前问题，要求输出：

- 只输出一个独立、可检索的中文问题；
- 不回答问题；
- 不添加知识库没有的信息；
- 无法改写时原样返回当前问题。

## 9. 执行流程

### 9.1 创建运行

1. 校验权限、数据集存在、至少一个用例；
2. 同一数据集已有 `pending`/`running` 运行时返回 `409`；
3. 校验文档：存在、未删除、索引 `ready`；失效文档对应轮次标记 `invalid`；
4. 把用例和轮次快照写入 `eval_run_items`；
5. 创建 `eval_runs`，状态 `pending`，`total_items` = 轮次数；
6. 提交事务后投递 Celery 任务 `run_evaluation`；
7. 返回 `202` 和 `run_id`。

### 9.2 Worker 执行

- 每个任务使用独立 `create_async_engine(..., poolclass=NullPool)` 和 session factory；
- 按用例分组，维护内存历史；
- 逐轮执行：
  1. 检查 `cancel_requested`；
  2. 选择检索问题（当前问题 / 历史改写）；
  3. 向量化并检索 top-k；
  4. 构造上下文和消息；
  5. 调用 LLM 生成回答；
  6. 计算检索与引用指标；
  7. 调用 DeepSeek 评分；
  8. 更新 `eval_run_items` 和 `eval_runs.completed_items`；
  9. 把本轮用户问题和助手回答追加到内存历史；
- 全部完成后计算聚合指标，状态 `succeeded`；
- 任务级异常：状态 `failed`，写入 `error`；
- 单轮异常：该轮 `error`，其他轮继续。

### 9.3 取消

- `POST /eval/runs/{id}/cancel` 设置 `cancel_requested = true`；
- Worker 在每轮开始前检查；
- 已完成的轮次保留结果，未完成标记 `cancelled`；
- 运行状态改为 `cancelled`。

### 9.4 历史隔离

评测不创建 `conversations` / `messages`，不调用写入型 `stream_chat`。复用：

- `embed_query`
- `_search_chunks`
- `_context`
- `_build_messages`
- LLM 流式生成
- 新增 `answer_for_eval`

多轮历史在内存中传递，运行结束后不保留对话。

### 9.5 并发与超时

- 同一数据集同时只允许一个运行；
- 单轮 LLM 生成超时沿用 `LLM_TIMEOUT_SECONDS`；
- 评分调用超时 60 秒，失败重试 2 次；
- 首版 Worker 串行执行轮次，后续可通过配置提高并发。

## 10. DeepSeek 评分设计

### 10.1 输入

只发送：

- 当前问题；
- 参考答案；
- 模型回答；
- 最近 3 轮历史（多轮时，用于理解指代）；
- 期望类型 `answerable` / `unanswerable`。

**不发送文档原文或检索片段**，避免额外数据外发；引用判断用规则计算。

### 10.2 输出

要求 DeepSeek 返回 JSON：

```json
{
  "score": 1,
  "passed": false,
  "refused": false,
  "reason": "回答与参考答案不一致"
}
```

- `score`：1–5；
- `passed`：是否达到 4 分；
- `refused`：是否拒答或明确表示无法回答；
- `reason`：一句话理由，最多 200 字。

### 10.3 评分规则

- `answerable`：语义等价给 4–5 分；部分正确给 2–3 分；错误或拒答给 1 分；
- `unanswerable`：正确拒答给 5 分，`refused=true`；编造答案给 1 分；
- 温度 0，最大输出 300 tokens；
- 解析失败或调用失败：该轮标记 `error`，不参与通过率计算，但在报告中展示。

  - 20 条可回答；
  - 6 条不可回答/拒答；
  - 4 条跨文档或边界问题。
- 多轮约 10 条：
  - 每条 2–3 轮；
  - 覆盖指代、追问、上下文切换；
  - 逐轮有参考答案和必引文档。

## 12. API 设计

所有接口前缀 `/api/v1`，除特别说明外要求 `require_evaluator`。

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/eval/datasets` | evaluator | 数据集列表 |
| POST | `/eval/datasets` | evaluator | 新建数据集 |
| PATCH | `/eval/datasets/{id}` | evaluator | 修改名称/描述 |
| DELETE | `/eval/datasets/{id}` | evaluator | 归档数据集 |
| GET | `/eval/datasets/{id}` | evaluator | 数据集详情（含用例/轮次） |
| POST | `/eval/datasets/{id}/import` | evaluator | 导入 JSONL |
| GET | `/eval/datasets/{id}/export` | evaluator | 导出 JSONL |
| POST | `/eval/datasets/{id}/cases` | evaluator | 新增用例 |
| PATCH | `/eval/cases/{id}` | evaluator | 修改用例 |
| DELETE | `/eval/cases/{id}` | evaluator | 删除用例 |
| POST | `/eval/cases/{id}/turns` | evaluator | 新增轮次 |
| PATCH | `/eval/turns/{id}` | evaluator | 修改轮次 |
| DELETE | `/eval/turns/{id}` | evaluator | 删除轮次 |
| POST | `/eval/datasets/{id}/runs` | evaluator | 启动运行，body `{retrieval_mode}` |

- `403 AUTH_FORBIDDEN`

- `409 EVAL_RUN_IN_PROGRESS`
- `422 VALIDATION_ERROR`

## 13. 前端设计

### 13.1 导航

- 侧边栏新增“评测”，仅 `leader` 或 `user.can_evaluate` 显示。
- 路由：
  - `/evaluations`：数据集列表 + 最近运行 + 成员权限。
  - `/evaluations/[id]`：数据集详情、用例维护、导入导出、启动运行。
  - `/evaluations/runs/[id]`：运行报告与基线对比。

### 13.2 数据集页

- 数据集卡片：名称、用例数、轮次数、最近运行状态和时间。
- 新建/编辑数据集弹窗。
- 导入 JSONL：选择文件、显示导入成功/失败行号。
- 导出 JSONL。
- 用例表格：标题、类型、轮次数、必引文档、操作。
- 用例编辑弹窗：标题、标签、轮次列表；每轮问题、参考答案、类型、必引文档多选。
- 启动运行：选择检索模式（当前问题/历史改写），确认后跳转运行详情。

### 13.3 运行详情页

- 顶部：状态、进度条（completed/total）、开始/结束时间、发起人、检索模式、取消按钮。
- 汇总卡片：轮次通过率、回答通过率、平均分、检索命中率、引用精确率、拒答正确率、用例通过率。
- 分项指标表：可回答/不可回答分组。
- 结果表：用例、轮次、状态、检索命中、引用精确率、评分、是否拒答、耗时；可筛选失败/失效/错误。
- 点击行展开：问题、检索问题、参考答案、模型回答、引用片段、评分理由、错误信息。
- 基线选择器：同数据集的历史运行；展示指标 delta、新增失败、已修复。
- 导出 JSONL/CSV。

### 13.4 成员权限页

- 仅领导可见。
- 员工列表：姓名、用户名、角色、`can_evaluate` 开关。
- 开关调用 `PATCH /eval/permissions/{user_id}`。
- 领导自己不可被关闭。

## 14. 报告与基线

### 14.1 运行结果保存

- 每次运行保存指标 JSON 和逐轮结果；
- 用例/轮次内容快照，后续编辑不影响历史；
- 运行不可修改，只能删除（首版不提供删除入口，归档由数据库维护）。

### 14.2 基线对比

- 用户手动选择同一数据集的历史运行作为基线；
- 对比：
  - 汇总指标差值；
  - 用例级新增失败/新增通过；
  - 轮次级新增失败/新增通过；
  - 失效/错误数量变化。
- 不做自动回归门槛，由人判断。

### 14.3 导出

- JSONL：逐轮结果，包含问题、参考答案、检索文档、引用、回答、评分、指标；
- CSV：适合表格分析；
- 导出不包含 API Key、完整文档原文。

## 15. 非功能与数据边界

- 评测执行不写入 `conversations` / `messages`；
- DeepSeek 评分只发送问题、参考答案、模型回答和历史，不发送文档原文；
- 草稿生成经确认后发送文档分块片段，不发送完整文件；
- 评分/生成失败重试 2 次，仍失败标记 `error`；
- 运行记录保留，不自动清理；
- 同一数据集只允许一个运行；
- 所有评测接口校验权限和数据集归属；
- 不把 DeepSeek Key 写入日志或前端。

## 16. 验收标准

1. 迁移和权限：`can_evaluate` 字段、领导授权、导航可见性正确。
2. 数据集/用例/轮次可增删改查；JSONL 导入导出可用，错误行号明确。
3. 启动运行后 Celery 异步执行，进度实时更新，可取消。
4. 单轮可回答：检索命中、引用精确率、评分、通过判定正确。
5. 单轮不可回答：正确拒答判定正确。
6. 多轮：逐轮评分，历史传递正确；`question` 和 `rewritten` 两种模式可分别运行并对比。
7. 文档失效：运行前标记 `invalid`，不参与指标，报告可见。
8. 基线对比：指标 delta、新增失败/修复正确展示。
9. 运行结果可导出 JSONL/CSV。
10. 被授权员工可运行、查看、维护；未授权员工访问返回 403。
11. 初始 30 单轮 + 10 多轮草稿生成、人工审核、导入并完成一次完整运行。
12. 评测不产生新的 `conversations` / `messages` 记录。

## 18. 风险与待确认

### 18.1 风险

- LLM 评分存在波动：温度 0、单评委、保存理由；必要时后续增加多评委。
- 合成用例可能偏离真实问题：必须人工审核后导入。
- 历史改写会增加 LLM 调用和运行时间：作为可选模式，不作为默认生产检索。
- 文档变更导致用例失效：运行前校验并标记，不误判为模型失败。
- 30–50 条用例覆盖有限：首版用于回归趋势，不宣称全面质量。

### 18.2 需要你确认的事项

1. 语料清理清单：是否删除《员工手册1》和 P1 测试文档；是否保留/重命名《Phase 4 班车测试》；是否新增《IT 权限流程》《报销流程》《会议室预订》三份文档。
2. 评测数据集初始名称（建议 `RAG 回归集 v1`）。
3. 评分提示词语言（建议中文）和 1–5 分标准是否按本设计执行。
4. 单用例最多 5 轮、每数据集同时只跑一个运行，是否接受。
5. 首版是否只做“手动选择基线”，不加自动回归门槛。
