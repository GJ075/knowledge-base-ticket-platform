# 13 文档批量删除与回收站设计

> 状态：已实现（2026-11-10），迁移 `0007_document_trash`。
> 日期：2026-11-10
> 关联文档：[03 数据模型](03-数据模型与数据库设计.md)、[04 API](04-API接口设计.md)、[06 前端](06-前端页面与交互设计.md)、[08 测试手册](08-首版测试手册.md)

## 1. 背景

文档列表目前只支持逐条删除。测试期间上传了 361 篇 RGB 段落，清理时需要一页 20 条、逐条点删除，再翻页重复，成本和误操作风险都高。同时，现有删除不可恢复：

- 领导删除会立即删除 `document_chunks` 和 MinIO 对象；
- 员工删除走审批，但审批通过后同样直接清理，无法还原。

本设计增加三件事：

1. 文档页多选与批量删除；
2. 删除后的「回收站」，可长期恢复；
3. 文档审批页的批量通过/驳回。

## 2. 已确认决策

| 项 | 决策 |
|---|---|
| 批量操作范围 | 仅批量删除，不做批量重索引、打包下载 |
| 多选范围 | 每行复选框，表头全选仅作用于当前页 |
| 使用权限 | 领导直接删除；员工批量提交待审批变更 |
| 防误操作 | 删除不弹确认，执行后进入回收站，可长期恢复 |
| 回收站保留 | 长期保留，手动彻底删除；不自动过期 |
| 彻底删除 | 清除分块与 MinIO 对象，不可恢复 |
| 审批页 | 支持批量通过/批量驳回 |
| 部分失败 | 跳过并汇总原因，不整批回滚 |

## 3. 范围

### 3.1 首版包含

- 文档列表多选、全选当前页、批量删除（领导/员工两种模式）。
- 回收站：列表、搜索、分页、恢复、彻底删除（仅领导）。
- 审批页：多选、批量通过、批量驳回。
- 删除语义调整：删除只隐藏并保留数据，彻底删除才清理。
- 历史数据的迁移处理。

### 3.2 首版不包含

- 批量重新索引、批量下载、批量改标题。
- 跨页全选（一次选中全部筛选结果）。
- 自动清理策略（按天数自动彻底删除）。
- 普通员工访问回收站。
- 删除操作审计日志（沿用现有 document_changes 记录）。

## 4. 数据模型

### 4.1 `documents` 新增列

迁移 `0007_document_trash`。

| 列 | 类型 | 说明 |
|---|---|---|
| `deleted_at` | `timestamptz NULL` | 进入回收站的时间 |
| `purged_at` | `timestamptz NULL` | 彻底删除时间；非空表示不可恢复 |

保留现有 `is_deleted`，语义为 `deleted_at IS NOT NULL`，避免大范围改查询。

索引：

```sql
CREATE INDEX idx_documents_trash
ON documents (deleted_at DESC)
WHERE deleted_at IS NOT NULL AND purged_at IS NULL;
```

### 4.2 历史数据迁移

现有 `is_deleted = true` 的文档，删除时已经清理了分块和对象，无法恢复。迁移时标记为已彻底删除，避免出现在回收站：

```sql
UPDATE documents
SET deleted_at = updated_at,
    purged_at = updated_at
WHERE is_deleted = true;
```

## 5. 删除语义重构

### 5.1 领导删除（单条与批量一致）

1. 检查是否有待审批变更，有则跳过并记录原因；
2. `is_deleted = true`，`deleted_at = now()`；
3. **不再删除分块和 MinIO 对象**；
4. 提交事务，返回结果。

文档立即从列表、搜索和 RAG 检索中消失，但数据保留，可随时恢复。

### 5.2 员工删除

1. 检查是否有待审批变更，有则跳过；
2. 创建 `document_changes(action=delete, status=pending)`；
3. 文档保持可见，直到领导审批通过。

### 5.3 审批通过（delete 类型）

改为与领导删除一致：进入回收站，不清理数据。这样审批通过的误删也能恢复。

### 5.4 恢复

1. 仅 `deleted_at` 非空、`purged_at` 为空、且无待审批变更的文档可恢复；
2. `is_deleted = false`，`deleted_at = NULL`；
3. 分块与对象仍在，恢复后立即回到检索结果，无需重新索引。

### 5.5 彻底删除

1. 删除该文档的 `document_chunks`；
2. 删除 MinIO 对象（失败只记录日志，不阻断）；
3. `purged_at = now()`；
4. 文档行保留，用于历史追溯，但不再出现在任何列表。

## 6. API 设计

前缀 `/api/v1`。批量接口单次最多 100 个 ID，前端当前页最多 20 条。

### 6.1 批量删除

`POST /documents/batch-delete`

```json
{ "ids": ["UUID", "UUID"] }
```

领导响应 `200`：

```json
{
  "mode": "direct",
  "deleted": [{"id": "UUID", "title": "RGB-1"}],
  "skipped": [{"id": "UUID", "title": "员工手册", "reason": "该文档已有待审批变更"}]
}
```

员工响应 `202`：

```json
{
  "mode": "pending_approval",
  "deleted": [],
  "submitted": [{"id": "UUID", "title": "RGB-1"}],
  "skipped": [{"id": "UUID", "title": "员工手册", "reason": "该文档已有待审批变更"}]
}
```

- 不存在的 ID 跳过，原因「文档不存在」；
- 已删除的 ID 跳过，原因「文档已在回收站」；
- 部分失败不影响其余文档。

### 6.2 回收站列表

`GET /documents/trash?keyword=&page=1&page_size=20`（仅领导）

返回与文档列表结构一致，额外包含 `deleted_at`，只返回 `purged_at IS NULL` 的记录，按 `deleted_at` 倒序。

### 6.3 恢复

`POST /documents/trash/restore`

```json
{ "ids": ["UUID"] }
```

响应 `200`：`{"restored": [{"id": "UUID", "title": "..."}], "skipped": [...]}`

跳过原因：文档不在回收站、已彻底删除、存在待审批变更。

### 6.4 彻底删除

`POST /documents/trash/purge`

```json
{ "ids": ["UUID"] }
```

响应 `200`：`{"purged": [...], "skipped": [...]}`。不可恢复，前端要求输入确认文字。

### 6.5 批量审批

`POST /document-changes/batch-approve`（仅领导）

```json
{ "ids": ["UUID"], "comment": "批量清理测试文档" }
```

`POST /document-changes/batch-reject`

```json
{ "ids": ["UUID"], "comment": "请勿删除，保留" }
```

- 只处理 `status=pending` 的变更，其余跳过并记录原因；
- 驳回的 `comment` 必填，整批共用一条意见；
- 通过与单条审批逻辑一致，add/update/delete 三类动作分别处理；
- 响应：`{"processed": [...], "skipped": [...]}`。

### 6.6 错误码

沿用现有错误码，不新增：

- `AUTH_FORBIDDEN`：员工访问回收站；
- `VALIDATION_ERROR`：ID 为空或超过 100 条；
- `DOC_CHANGE_ALREADY_PENDING`：单条删除时仍返回 409，批量时改为跳过。

## 7. 前端设计

### 7.1 文档页

- 表格新增复选列；表头复选框只控制当前页，全选状态随翻页/筛选重置。
- 选中数量大于 0 时，表头操作区显示「批量删除（N）」。
- 点击后调用批量删除：
  - 领导：提示「已移入回收站 12 篇，跳过 1 篇」，提供「去回收站」链接；
  - 员工：提示「已提交 12 条删除申请，等待领导审批」。
- 结果中含跳过项时，用可展开的提示条列出原因。
- 操作完成后清空选择并刷新列表。

### 7.2 回收站页 `/documents/trash`（仅领导）

- 导航「文档」下新增入口，仅领导可见。
- 表格列：标题、文件名、大小、上传人、删除时间；支持关键词搜索与分页。
- 多选与全选当前页；操作：恢复、彻底删除。
- 彻底删除弹窗显示数量与前 5 个标题，要求手动输入「彻底删除」后才能提交。

### 7.3 审批页

- 待审批列表新增复选列与全选当前页。
- 选中后显示「批量通过」「批量驳回」。
- 批量通过弹窗可填审批意见。
- 批量驳回弹窗必须填写意见，整批共用。

### 7.4 撤销与提示

- 删除不弹确认框；执行后 toast 提示并提供「回收站」入口，替代短时撤销。
- 彻底删除不可撤销，必须二次确认。

## 8. 权限与安全

| 操作 | 员工 | 领导 |
|---|---|---|
| 批量删除 | 提交待审批变更 | 直接移入回收站 |
| 查看回收站 | 403 | 允许 |
| 恢复 | 403 | 允许 |
| 彻底删除 | 403 | 允许 |
| 批量审批 | 403 | 允许 |

- 批量接口逐条校验，跳过无权限/状态不符的记录，不因单条失败整批报错。
- 彻底删除属于不可逆操作，后端不做软删除兜底，前端必须二次确认。
- 回收站数据不参与检索，不进入 RAG 上下文。

## 9. 兼容与影响

- 现有单条删除接口保留，内部改为新的删除语义（进入回收站）。
- 现有「删除文档」的 API 响应不变。
- 已删除的历史文档在迁移后视为已彻底删除，不出现在回收站。
- 文档审批通过 delete 后，行为从「彻底删除」变为「进入回收站」，属于行为变化，需要在测试手册中注明。
- 存储占用会因回收站增加，首版接受，后续可加「按天数自动清理」。

## 10. 验收标准

1. 领导批量删除 5 篇：列表消失，回收站出现 5 篇，RAG 检索不到。
2. 恢复其中 1 篇：立即回到列表与检索结果，无需重新索引。
3. 彻底删除 1 篇：分块与 MinIO 对象被清理，无法恢复。
4. 员工批量提交：生成对应数量的待审批变更；已有待审批变更的文档被跳过并提示。
5. 审批页批量通过含 delete 的变更：文档进入回收站。
6. 批量驳回：意见必填，文档保持可见。
7. 未授权员工访问回收站接口返回 403。
8. 迁移后，历史已删除文档不出现在回收站。
9. 批量操作中部分文档不存在或已在回收站时，其余正常处理并汇总原因。

## 11. 实施阶段

| 阶段 | 内容 |
|---|---|
| A | 迁移、删除语义重构、批量删除接口 |
| B | 回收站接口与页面 |
| C | 审批页批量通过与驳回 |
| D | 文档页多选、提示与回归测试 |

## 12. 风险

- 回收站长期保留分块与对象，存储会增长；需要后续的自动清理或容量监控。
- 历史已删除文档不可恢复，迁移只能标记，不能补救。
- 彻底删除不可逆，前端确认与服务端权限必须同时生效。
- 批量删除的「跳过汇总」需要前端清晰展示，否则用户误以为全部成功。

实测结果：

- 领导批量删除 2 篇 → 回收站可见，列表与检索消失；
- 恢复 1 篇 → 立即回到列表（分块未删除）；
- 彻底删除 1 篇 → 回收站消失；
- 员工批量提交 2 条 → 审批页批量通过 → 文档进入回收站 → 恢复成功；
- 批量驳回 → 文档保持可见；
- 员工访问回收站返回 403。
