## 项目一句话

单租户的企业知识库问答与工单处理系统：员工和领导都能基于企业文档提问；员工修改知识库需领导审批；工单按明确的状态机流转并由领导把关。

## 关键决策摘要

1. **独立项目**：与已有的 `企业知识库` 项目无关，新建 `企业知识库工单系统`。
2. **单租户、两种角色**：员工、领导；领导权限更高，但问答历史仍仅本人可见。
3. **文档审批**：员工新增/修改/删除文档生成待审变更；领导直接生效；审批期间旧版本继续可检索。
4. **工单 8 状态**：`new / pending_assignment / in_progress / completed / pending_user_confirmation / returned / modified / resolved`。
5. **工单终审**：员工提交的工单由领导终审；领导提交的工单走"待用户确认"，确认人为提交领导本人；任何"修改完成"都要领导审核后再回处理中。
6. **RAG 首版**：固定长度切分、top-5 向量检索、无 reranker、DeepSeek 流式生成、答案带文档名+片段引用、无结果由 prompt 约束拒答。
7. **数据边界**：文档原文、向量、附件只存本机；仅"用户问题 + top-5 片段"发送到 DeepSeek。
8. **首版只做主体框架**：不追求检索准确率、UI 精细度和边界完善；测试由用户按手册执行，再按结果迭代。

## 设计边界

- 本设计只覆盖首版主体框架。
- 拒答阈值、置信度提示、人工兜底、审计记录只写入 [09-后续规划](09-后续规划.md)，不进入首版代码。
- 工单完成后只作为工单记录保存和查询，不进入 RAG 知识库。
